# Contributing to Vibe Coding Checklist

Thanks for helping developers ship more reliable software.

## Good contributions

- Make a checklist item **testable** instead of abstract.
- Explain a real failure mode, with an example or reproduction.
- Describe when a technology is **not** appropriate.
- Suggest the simplest sound option before advanced infrastructure.
- Add stack-specific examples, references, or evidence templates.
- Fix incorrect information, terminology, or broken links.

## How to contribute

1. Search existing issues and open a focused issue if the change needs discussion.
2. Fork this repository or create a feature branch.
3. Keep pull requests small and update related checklist items and the CSV when changing topic inventory.
4. Explain the scenario, rationale, and how the guidance was tested.
5. Do not include passwords, credentials, customer data, or proprietary source code.

## Review criteria

Clarity, accuracy, practical relevance, security, verifiability, and restraint. No vendor endorsements without clear technical rationale.

Please treat all community contributors respectfully.
